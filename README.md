## Краткое описание работы

В данной лабораторной работе разработано RESTful API для управления задачами с использованием Entity Framework Core и SQLite. Реализован полноценный CRUD, поиск с фильтрацией, пагинация, статистика, а также миграции для управления схемой базы данных.

---

## Полезные команды dotnet ef

**dotnet ef migrations add <Name>** — создать новую миграцию на основе изменений в моделях

**dotnet ef database update** — применить все неприменённые миграции к базе данных

**dotnet ef migrations remove** — удалить последнюю миграцию (если она ещё не применена)

**dotnet ef migrations list** — показать список всех миграций с указанием статуса

**dotnet ef database drop** — удалить файл базы данных

**dotnet ef migrations script** — сгенерировать SQL-скрипт из всех миграций

**dotnet ef database update <MigrationName>** — откатить или обновить БД до конкретной миграции

**dotnet ef migrations add <Name> --output-dir <Path>** — создать миграцию в указанной папке

**dotnet ef database update --verbose** — применить миграции с подробным выводом SQL-запросов

## Список всех реализованных маршрутов

**GET /api/tasks** — получить все задачи

**GET /api/tasks/{id}** — получить задачу по ID

**GET /api/tasks/search?query=&priority=&completed=** — поиск задач с фильтрацией по тексту, приоритету и статусу

**GET /api/tasks/stats** — получить статистику (общее количество, выполненные, невыполненные, процент выполнения, группировка по приоритету, созданные за неделю)

**GET /api/tasks/paged?page=1&pageSize=10** — получить задачи с пагинацией

**GET /api/tasks/overdue** — получить просроченные задачи (срок выполнения в прошлом)

**POST /api/tasks** — создать новую задачу

**PUT /api/tasks/{id}** — обновить задачу

**PATCH /api/tasks/{id}/complete** — переключить статус выполнения задачи

**DELETE /api/tasks/{id}** — удалить задачу

## Итоговая сравнительная таблица

| Концепция          | Хранение в памяти          | EF Core + SQLite                               |
|--------------------|----------------------------|------------------------------------------------|
| Хранение данных    | `static List<T>` в RAM     | Файл `.db` на диске                            |
| После перезапуска  | Данные пропадают           | Данные сохраняются                             |
| Поиск по условию   | LINQ to Objects            | LINQ to Entities → SQL                         |
| Создание структуры | Не нужно                   | Миграции (`dotnet ef`)                  |
| Начальные данные   | Хардкод в коде             | `HasData()` в миграции                         |
| Получение данных   | `list.FirstOrDefault(...)` | `await db.Table.FindAsync(id)`                 |
| Добавление         | `list.Add(item)`           | `db.Table.Add(item)` + `SaveChangesAsync()`    |
| Удаление           | `list.Remove(item)`        | `db.Table.Remove(item)` + `SaveChangesAsync()` |
| Масштабируемость   | Ограничена RAM             | Гигабайты данных                               |
| Транзакции         | Нет                        | Встроены в EF Core                             |

## Главные выводы

1. **EF Core** — это переводчик между C# и SQL. Вы пишете LINQ, он пишет SQL.

2. **Миграции** — это система контроля версий для структуры БД. Так же, как Git для кода.

3. **Code First**  удобнее, чем писать SQL вручную: изменил класс → создал миграцию → база обновлена.

4. **SaveChangesAsync()** — ключевой момент. До него все изменения живут только в памяти.

5. **async/await** при работе с БД — это не опционально, а стандарт. Блокировать поток на время ожидания БД — плохая практика.
